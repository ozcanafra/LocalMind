Second-chance (Clock) Algoritması
TANIM
Second-chance algoritması, FIFO tabanlı bir page replacement algoritmasıdır. FIFO'ya göre
seçilen page'e değiştirilmeden önce ikinci bir şans verir. Clock (saat) algoritması olarak da
bilinir.
Temel Çalışma Mantığı:
• Değiştirilecek page seçilirken referans biti incelenir.
• Referans biti = 0 → page değiştirilir.
• Referans biti = 1 → page'e ikinci şans verilir; referans biti 0'a çekilir, varış zamanı sıfırlanır,
sonraki page'e geçilir.
• Uygulama için dairesel bir kuyruk (circular queue) kullanılır.
• Pointer, referans biti 0 olan bir page bulana kadar ilerler ve ilerledikçe bitleri temizler.
Önemli Özellikler:
• Bellekte zaten olan bir page'e tekrar başvuru → referans biti 1 yapılır (ödül).
• İkinci şansını kullanan page, diğer tüm page'ler değiştirilene kadar korunur.
• Çok sık kullanılan bir page referans bitini korursa asla değiştirilmez.

A ÇIKAR

Page-Buffering Algoritması:
• Sistem, boş/müsait frame havuzu tutar.
• Page hatası → kurban frame seçilir → istenen page, kurban yazılmadan önce boş frame'e
yerleştirilir.
• Process beklemeden devam edebilir; kurban sonra yazılır ve boş havuza eklenir.
• Değiştirilmiş page listesi: Disk boştayken değiştirilmiş page'ler diske yazılır, dirty bit sıfırlanır
→ gelecekte I/O tasarrufu.
• Boş frame içerik kaydı: Frame'de hangi page'in olduğu bilinirse, page zaten oradaysa I/O
gerekmez.
4. Frame Tahsisi (Allocation of Frames)
TANIM
Her process'e kaç frame tahsis edileceğini belirleyen politikalar. Az frame → yüksek page
hatası → yavaş yürütme. Minimum frame sayısı mimari tarafından, maksimum ise fiziksel
bellek miktarıyla sınırlandırılır.

3. Reclaiming Pages (Page'lerin Geri Alınması):
• Boş frame listesi sıfıra düşmeden belirli bir eşik değerinde tutulur.
• Eşiğin altına düşünce kernel page'leri geri almaya başlar → maksimum eşiğe ulaşana kadar
devam eder.
• Maksimum eşiğe ulaşınca reclaiming askıya alınır.
4. NUMA (Non-Uniform Memory Access):
• Birden fazla CPU'lu sistemlerde bazı bellek bölgelerine erişim daha hızlıdır.
• Amaç: process'in çalıştığı CPU'ya mümkün olduğunca yakın frame tahsis etmek.
• Solaris çözümü: lgroups (locality groups) — CPU ve belleği gecikme aralığına göre gruplar.
5. Thrashing
TANIM
Bir process, komutlarını yürütmekten daha fazla zaman paging için harcıyorsa thrashing
olmuştur. Page hatası oranı muazzam artar, EAT (Effective Access Time) yükselir, CPU
kullanımı düşer.
Thrashing Döngüsü (Cascade):
• Process daha fazla frame'e ihtiyaç duyar → diğer process'lerden frame alır.
• O process'ler de başkasından frame alır → herkes page hatası yapar.
• Process'ler paging için sıraya girer → hazır kuyruk boşalır → CPU kullanımı düşer.
• CPU scheduler azalan kullanımı görür → multiprogramming derecesini artırır → durum daha
kötüleşir!
EZBER
Thrashing = process tüm zamanını paging'e harcıyordur, gerçek iş yapılmıyordur.
Multiprogramming derecesi düşürülünce durur.
Thrashing'i Önleme — Locality Model:
• Process yürütülürken bir bölgeden diğerine hareket eder.
• Bölge (locality): Birlikte aktif olarak kullanılan page kümesi.
• Fonksiyon çağrılınca → yeni bölge tanımlar; çıkılınca → bölge terk edilir.
• Thrashing'i önlemek için process'e o anki bölgesini tutacak kadar frame sağlanmalıdır.
DİKKAT
Pratikte en iyi çözüm: fiziksel bellek eklemek. Tüm working set'leri aynı anda bellekte
tutacak kadar RAM → thrashing ve swapping önlenir.
6. Working-Set Modeli
TANIM
Locality modeline dayanan bu model, Δ (delta) parametresiyle tanımlanan bir pencere
içindeki en son page referanslarını izler. Bu penceredeki page kümesi working-set'tir.
Temel Kavramlar:
• Working-set window (Δ): İncelenen son Δ adet referans.
• WSSᵢ: i. process'in working-set boyutu (ihtiyaç duyduğu frame sayısı).
• D = Σ WSSᵢ: Toplam talep frame sayısı.
• D > m (toplam fiziksel frame) → thrashing kaçınılmaz.
Δ Seçiminin Önemi:
Δ Değeri
Çok küçük
Sonuç
Tüm bölgeyi kapsamaz → eksik working-set
Çok büyük
Birkaç bölgeyle çakışır → gereksiz page tutulur
Sonsuz
İşlemin tüm yaşamı boyunca kullandığı tüm page'ler
İşletim Sistemi Kararları:
• Her process'in working-set'i izlenir; WSSᵢ kadar frame tahsis edilir.
• Yeterli frame varsa → yeni process başlatılabilir.
• D > m olursa → bir process askıya alınır (page'leri swap out), frame'leri diğerlerine dağıtılır.
• Working-set stratejisi: multiprogramming derecesini yüksek tutarken thrashing'i önler → CPU
kullanımını optimize eder.
SINAVD
A ÇIKAR
Sınav sorusu tipi: Δ=10 iken t1 anında working-set nedir? → Son 10 referansa bak, tekrarları
kaldır, küme = working-set.
7. Page-Fault Frequency (PFF)
TANIM
Thrashing'i working-set modeline göre daha doğrudan kontrol eden bir strateji. Page hatası
oranı üst/alt sınırlarla yönetilir.

Aralıkta

Working-Set ile Page Fault Rate İlişkisi:
• Bölge geçişlerinde page hatası oranı tepe yapar (yeni page'ler yükleniyor).
• Bölge içinde yürütme sürerken page hataları azalır.
• Yeterli bellek varsa (thrashing yoksa) bu döngüsel desen düzenli şekilde devam eder.
8. Gerçek İşletim Sistemi Örnekleri
Linux:
• Demand paging + Second-chance (clock) algoritmasına benzer genel page değiştirme politikası.
• active_list: Aktif kullanımda olduğu düşünülen page'ler.
• inactive_list: Son başvurulmamış, geri alınmaya uygun page'ler.
• Her page'in accessed biti vardır → başvuru gelince 1 yapılır; periyodik olarak sıfırlanır.
• En az kullanılan → active_list'in önüne gelir → inactive_list'e taşınır.
• Inactive'den tekrar başvurulursa → active_list'in arkasına döner.
• Boş bellek eşiğin altına düşerse → kernel inactive_list'i tarar, page'leri boş frame havuzuna geri
alır.
Windows 10:
• Clustering: Page hatası oluşunca sadece hatalı page değil, önceki ve sonraki birkaç page de
getirilir (locality'den yararlanır).
• Working set minimum: Process'in bellekte sahip olması garanti edilen minimum page sayısı.
• Working set maximum: Yeterli bellek varsa ulaşılabilen üst sınır (bu sınır aşılabilir de).
• Second-chance (clock) algoritması + local ve global değiştirme kombinasyonu.
• Automatic working-set trimming: Boş bellek eşiğin altına düşünce process'lerin
working-set'inden page kaldırılır; minimum'a ulaşana kadar devam eder.
